#+TITLE: spyglass
#+OPTIONS: toc:nil

Spyglass mirrors live buffers from one Emacs into another, on the same host or across SSH. An owner shares buffers; a viewer opens read-only mirrors of them that follow every change, with faces, display properties, overlays and the owner's cursor, and sends the keys typed in them back. Shells, comint buffers and terminals (Eat, Ghostel, vterm) mirror as well as ordinary buffers, including terminals that write without modification hooks; a broken connection comes back on its own and mirrors resume where they were.

It is a library: it knows nothing of what the buffers hold. A session manager such as drover uses it to show, on one machine, agent sessions living in another machine's Emacs.

* Requirements

- Emacs 30.1 or later, for its built-in JSON parser; tested on 31.1 on macOS (the Mac port) and on Windows (MSYS2 UCRT64), and on 30.2 with Cocoa. No other package.
- For another host: an SSH client whose =-W= forwards standard input and output to a port (OpenSSH, including Windows's OpenSSH server), and a shell there knowing =cat=.
- Optionally Eat, Ghostel or vterm on the owner: their adapters load with them.

* Installation

#+begin_src emacs-lisp
  (use-package spyglass
    :ensure (:host github :repo "vleonbonnet/spyglass"))
#+end_src

* Quick start

** On the owner

#+begin_src emacs-lisp
  (spyglass-server-start)                     ; 127.0.0.1, random port and token
  (spyglass-share (get-buffer "*shell*"))
#+end_src

The server listens on 127.0.0.1 only and writes its port and a random token to =spyglass-registration-file= (=~/.emacs.d/spyglass/server.json=), readable by you alone. Interactively, =M-x spyglass-share-current-buffer= starts the server and shares the current buffer.

** On the viewer

#+begin_src emacs-lisp
  (setq conn (spyglass-connect (spyglass-ssh-transport "otherhost") :name "otherhost"))
  (spyglass-connection-shares conn)             ; announced by the owner
  (pop-to-buffer (spyglass-open conn "*shell*"))
#+end_src

=spyglass-ssh-transport= reads the remote registration file with =ssh HOST cat FILE= (=spyglass-remote-registration-file=), then runs =ssh -W 127.0.0.1:PORT HOST= for the stream; =spyglass-ssh-program= names the SSH client. Once a stream so made has authenticated, connecting again runs only the second, until one fails to. Interactively: =M-x spyglass-connect-host=, then =M-x spyglass-open-share=.

** In a mirror

Printing characters, =RET=, =M-RET=, =TAB=, =DEL=, the arrows and =ESC= go to the owner; =C-c C-c=, =C-c C-d=, =C-c C-z= and =C-c C-j= send control characters, =C-c C-q= the next key, =C-c C-s= a string; =C-c C-f= toggles following the owner's cursor; =C-c C-k= closes the mirror. Point in a mirror is yours, to read where you like; the owner's cursor shows where typing goes, the input of a shell, and typing brings point back to it. In a shell, typing and the keys edit the input at that cursor, =RET= submits it. The mode line is the owner's, as its window renders it there (or what =spyglass-mirror-mode-line-function= gives while no window shows the buffer there), followed by where the mirror comes from, whether it is live, reconnecting or closed, the size of a terminal and whether it is read only; the header line is the owner's, if it has one. The owner's face remapping applies too, and faces the viewer lacks show with the owner's attributes, those of display strings and overlay strings included.

* API

Nothing below prompts; every function returns at once, and what happens on the network is reported through callbacks and hooks, never signaled into timers or process filters.

** Sharing

- =(spyglass-share &optional BUFFER &key ID READ-ONLY INPUT CAPTURE NEEDS-WINDOW PEERS SIZE-POLICY)= :: Share BUFFER (default: current) under ID (default: its name) and return the share. READ-ONLY refuses input, or, a function of a viewer's connection, refuses that viewer's input when it returns non-nil, each viewer being told whether it may type; INPUT is a function applying viewers' input instead of the default; CAPTURE is =auto=, =shadow= or =direct= (see [[file:doc/design.org][the design notes]]); NEEDS-WINDOW non-nil parks the buffer while viewers watch it and no window shows it (see [[*Terminals][Terminals]]), =auto= (the default) asks the buffer's =spyglass-needs-window=. PEERS, a predicate of a connection, makes the share visible to the peers it accepts alone: the others are not told of it and cannot open it. SIZE-POLICY is the share's own =spyglass-size-policy=. Sharing again updates the options given, closing the mirrors of viewers PEERS no longer accepts. Mirrors are never shared.
- =(spyglass-unshare BUFFER-OR-SHARE)= :: Stop sharing; viewers' mirrors close with the reason "unshared". Killing a shared buffer does the same ("killed").
- =(spyglass-shares)=, =(spyglass-share-of BUFFER)=, =(spyglass-share-viewers SHARE)=, =(spyglass-share-stats SHARE)= :: Shares, a buffer's share, its subscriptions, its counters and samples (main-thread ticks, latencies, bytes).
- =(spyglass-notify &optional BUFFER BEG END PROPS-ONLY)= :: Tell spyglass that BUFFER changed between BEG and END without modification hooks. Code writing with =inhibit-modification-hooks= bound should call it, as the Eat and Ghostel adapters do; without it changes are still found, by comparing the whole buffer at most every ten times the cost of a comparison.
- =spyglass-input-function= (buffer-local) :: How viewers' input applies in this buffer: a function of (KIND VALUE), KIND =string= with text or =key= with a key such as ="RET"=. Adapters set it; =spyglass-default-input= types into comint buffers, sends to processes as a terminal would, or inserts at point.
- =spyglass-submit-function= (buffer-local) :: The command RET runs in a comint buffer, =comint-send-input= by default; a front end such as agent-shell sets =agent-shell-submit= here.
- =spyglass-point-function= (buffer-local) :: The position viewers follow, shown as the owner's cursor in mirrors; terminal adapters give the terminal's cursor. By default, the input point of a comint buffer (=spyglass-comint-input-point=: point while it is in the input after the prompt, else the end), where viewers' text goes and which moves as they type, else the point of a window of the owner's showing the buffer, else the buffer's point.
- =spyglass-key-commands= (buffer-local) :: Commands viewers' keys run in this buffer, an alist (KEY . COMMAND), KEY as a viewer sends it (="RET"=, ="C-c"= for a mirror's =C-c C-c=): for a front end submitting or interrupting with commands of its own, as agent-shell's =RET= runs =agent-shell-submit=. Keys are never looked up in the owner's keymaps: the application lists what it allows. Comint buffers honor it. Viewers' input runs with =inhibit-interaction=: what would ask the owner's user fails instead.
- =spyglass-needs-window=, =spyglass-park-function= (buffer-local) :: The buffer changes only while a window shows it; the function run once it is parked. Ghostel's adapter sets them.
- =spyglass-refit-function=, =spyglass-terminal-size-function= (buffer-local) :: Non-nil makes the share a terminal its viewers size: a function making the terminal take its size again, which it finds through =window-adjust-process-window-size-function=, and one returning its size =(COLUMNS . ROWS)=. =spyglass-refit-process= suits terminals sizing their process through its =adjust-window-size-function=, as Eat and vterm do; a comint buffer in a pty may set it too.
- =spyglass-size-policy= :: Whose window sizes a terminal several parties show: =latest= (the default), =smallest= or =owner=. =spyglass-max-terminal-size= bounds what viewers may ask for.
- =(spyglass-parking-frame-p FRAME)=, =(spyglass-window-cells WINDOW)= :: Whether FRAME is a parking frame, for code walking frames; the size of WINDOW in cells, as terminals and viewers count it.
- =spyglass-share-functions=, =spyglass-share-state-functions= :: Hooks run on each new share, and on a share's events (=subscribed=, =unsubscribed=, =unshared=).

** Connecting

- =(spyglass-server-start &key PORT FILE)=, =(spyglass-server-stop)=, =(spyglass-server)= :: The listener on 127.0.0.1, its registration file, the running server.
- =(spyglass-connect TRANSPORT &key NAME CALLBACK PLIST)= :: Connect through TRANSPORT and return the connection, which connects again whenever its stream breaks, until =spyglass-disconnect=. CALLBACK gets =(CONNECTION EVENT DATA)= for =state=, =error= and =shares=.
- Transports: =(spyglass-ssh-transport HOST &key PROGRAM FILE ARGS)=, =(spyglass-file-transport &optional FILE)= for this host, =(spyglass-tcp-transport HOST PORT TOKEN)=. A transport is any function called with a continuation DONE, which it calls with a process streaming to the peer's server and the token, or with nil and a message; drover can supply its own. Attempts never have Emacs wait for the network or another host: sockets connect without waiting, host names are resolved by another Emacs, SSH runs in processes whose sentinels carry on, and an attempt still going after =spyglass-connect-timeout= (20 s) fails. Only starting a process makes Emacs wait, as long as the system takes, usually under a millisecond: the SSH transport starts one per attempt once it knows the port, two before.
- =(spyglass-reconnect CONNECTION &optional FRESH)= :: Break the connection's stream, without telling the peer, and have it come back as after a network failure, mirrors and channels resuming: for an application finding its peer unresponsive. A connection made through a transport connects again, at once if it was waiting to; an accepted one waits for its peer. With FRESH, the delays of the attempts that may follow start over, for an application with reason to think the peer is back (the network changed, the machine woke). A write that fails drops its stream by itself.
- =(spyglass-connection-set-reconnect-delays CONNECTION DELAYS)=, =(spyglass-connection-next-attempt CONNECTION)= :: Delays of a connection's own between its attempts to connect again, instead of =spyglass-reconnect-delays=, the last repeating: for an application backing off a peer that stays unreachable, each attempt through SSH starting a process; and the seconds before the next attempt, nil while none is due.
- =(spyglass-disconnect CONNECTION)=, =(spyglass-connections)=, =(spyglass-connection-state CONNECTION)= (=connecting=, =open=, =reconnecting=, =closed=), =(spyglass-connection-shares CONNECTION)=, =(spyglass-list-shares CONNECTION CALLBACK)=, =(spyglass-connection-label CONNECTION)=, =(spyglass-connection-capable-p CONNECTION CAPABILITY)=.
- =(spyglass-connection-ending CONNECTION)= :: How the connection's last stream ended, a line, or nil while none did: =exited with status 255= or =killed by signal 15= for a process such as SSH, =closed= for a socket its peer closed, =dropped by this end= for a stream this Emacs broke, a write having failed, its peer silent, or =spyglass-reconnect= asked.  What the process wrote to its standard error goes to =spyglass-error-functions= as before.
- =spyglass-connection-state-functions=, =spyglass-shares-changed-functions=, =spyglass-error-functions= :: Hooks on every connection's state, a peer's shares, and errors.
- =spyglass-connection-attach-functions=, =spyglass-connection-detach-functions= :: Hooks run with a connection as each stream's handshake succeeds, and with (CONNECTION FINAL) as a stream ends, FINAL non-nil when the connection will not come back.
- =(spyglass-connection-set-heartbeat CONNECTION INTERVAL TIMEOUT)= :: Heartbeats of one connection: every INTERVAL seconds of silence, the peer dropped after TIMEOUT, instead of =spyglass-heartbeat-interval= and =spyglass-heartbeat-timeout=. Seconds, integers or floats, positive, INTERVAL below TIMEOUT, else an error; nil keeps the default. A silent peer is dropped within TIMEOUT and half the shorter of INTERVAL and TIMEOUT − INTERVAL.
- =spyglass-pace-window= :: Emacs on Windows writes to sockets without reading meanwhile, so that two Emacs on one Windows host writing to each other more than the system buffers would each wait for the other forever. A stream both of whose ends write so is paced: at most this much (64 KB) written and not yet read by the peer, frames in fragments of a quarter of it. Streams with an end elsewhere, as SSH from a Mac to Windows, are not paced. See [[file:doc/design.org][the design notes]].
- =spyglass-w32-pipe-size= :: The pipes between Emacs on Windows and SSH, for the streams of =spyglass-ssh-transport= (4 MB): Windows's own, 4 KB, or the 64 KB =w32-pipe-buffer-size= often set, held Emacs to about 1.5 MB/s sending through SSH.

** Channels

Applications built on spyglass talk over its connections through channels: named streams of messages, each message a JSON object. Peers announce channels as a capability (=ch=): a peer of the same protocol version predating them gets nothing on channels, and =(spyglass-channel-available-p CONNECTION)= tells whether a connection's peer handles them.

- =(spyglass-register-channel NAME HANDLER &key REQUEST ATTACH DETACH)= :: HANDLER gets =(CONNECTION MESSAGE)= for each message; REQUEST =(CONNECTION MESSAGE REPLY)= for each request, and calls REPLY once, now or later, with an answer or with nil and an error; ATTACH and DETACH hear the streams of connections whose peers handle channels open and end, as the hooks above.  =(spyglass-unregister-channel NAME)=.
- =(spyglass-channel-send CONNECTION NAME MESSAGE)= :: MESSAGE is a plist as =json-serialize= takes it (objects as plists, arrays as vectors, =:false=, nil as null); text JSON cannot carry, raw bytes or surrogates, is replaced by U+FFFD.  It arrives as =json-parse-string= returns it, never given to =read=.  Messages go in order while the stream lives; those queued when it breaks are dropped.
- =(spyglass-channel-request CONNECTION NAME MESSAGE CALLBACK &optional TIMEOUT)= :: CALLBACK gets =(REPLY ERROR)= once: the answer, or a message when the peer refused, no channel answers there, the time ran out (=spyglass-channel-request-timeout=) or the stream ended first.
- Large messages :: Past =spyglass-channel-chunk-size= (256 KB) a message goes in chunks, at most =spyglass-channel-window= (2 MB) of them unacknowledged, sent from timers in ticks of =spyglass-channel-tick-budget=; none may exceed =spyglass-channel-max-size= (32 MB), on either end.  On a stream whose end here is a pipe, as SSH's, the window is at most what the pipe holds, 64 KB on macOS and Linux, =spyglass-w32-pipe-size= (4 MB) for the SSH transport on Windows, in chunks of a quarter of it, to peers announcing chunks that small (=ck=): a write the pipe cannot take makes Emacs wait 20 ms.  =(spyglass-channel-stats CONNECTION)= counts messages, bytes and chunks.

** Mirrors

- =(spyglass-open CONNECTION SHARE-ID &key BUFFER-NAME CALLBACK BUFFER TITLE)= :: Open a mirror and return its buffer, which fills asynchronously. CALLBACK gets =(MIRROR EVENT DATA)= for =state= and =error=. BUFFER, the buffer of a mirror that closed, is opened in again rather than a new one, its windows kept, as when a connection lost for good is replaced by another; TITLE names the mirror in its header line instead of the share's identifier.
- =(spyglass-close MIRROR-OR-BUFFER)= :: Stop updating; the buffer stays. Killing a mirror closes it.
- =(spyglass-mirror-state BUFFER)= (=opening=, =live=, =reconnecting=, =closed=), =(spyglass-mirror-closed-reason BUFFER)=, =(spyglass-mirror-connection BUFFER)=, =(spyglass-mirror-share-id BUFFER)=, =(spyglass-mirror-owner-point BUFFER)=, =(spyglass-mirror-stats BUFFER)=, =(spyglass-mirrors &optional CONNECTION)=.
- =(spyglass-mirror-send-string STRING &optional BUFFER)=, =(spyglass-mirror-send-key KEY &optional BUFFER)= :: Send input to the owner. The owner's refusals come back through the mirror's callback and =spyglass-error-functions=.
- =spyglass-mirror-state-functions= :: Hook run with (BUFFER STATE).
- =spyglass-mirror-mode-line-function= (buffer-local, in a mirror) :: Function returning the mirror's mode line, a string, while its owner sends none: the owner renders its mode line only while a window there shows the buffer, as a mode line rendered without one shows another buffer in its parts reading the window.
- =spyglass-mirror-follow=, =spyglass-mirror-show-cursor= :: Follow and show the owner's cursor.
- =spyglass-mirror-size-delay= :: Seconds changes of windows gather before mirrors of terminals report their size.

* Terminals

Eat and Ghostel write their buffers with modification hooks inhibited; their adapters, loaded with them, tell spyglass the range written after each redraw, give the terminal's cursor and type through the terminal's own key handling. vterm's module writes with hooks; its adapter types through vterm's key translation.

Ghostel renders a terminal only through a window showing it. While viewers watch a Ghostel terminal and no window shows it on the owner, spyglass shows it in a /parking frame/: an invisible frame of its own on the owner's graphical display, never made visible, never focused, out of =other-frame=, desktops and tab bars, deleted as soon as a window shows the buffer, the buffer is unshared or killed, or the last viewer leaves. Redisplay does not draw it. An Emacs with no graphical frame (a daemon serving terminals only) cannot park: a hidden Ghostel terminal stands still there. Eat and vterm update without windows and are never parked.

A terminal has one size, laid out for by the programs in it. Viewers report the size of the window showing their mirror, in cells of their own font, when it opens and whenever it changes, and the owner's terminal takes the size =spyglass-size-policy= picks: by default that of the last party to type into it or select it, the owner included, as tmux's =latest=; =smallest= and =owner= are the alternatives. The owner's windows are never resized: while a viewer's size wins, they show the terminal at that size, until the owner types or selects it there again. A parked terminal is sized through its parking window; Eat's and vterm's through their resize functions, shown or not. Peers of an older version neither send sizes nor receive them, and work as before.

* Security

The server binds 127.0.0.1 only; other hosts reach it through SSH. Clients must present the 256-bit token of the registration file, compared in constant time. Frames are limited to 64 KB before authentication and 64 MB after. Nothing received is ever read or evaluated: headers are JSON, Lisp values in them are decoded as data, and the viewer reduces every face, display specification and string to forms redisplay shows without evaluating anything (no images, no =:eval=, no =when=, no function as a height). Input from a viewer reaches only the share's input function, and a share made =:read-only= refuses it. Frames waiting, to be sent or handled, while a peer sends without reading are bounded by =spyglass-queue-limit=, past which its stream is dropped. Sizes a viewer reports are bounded by =spyglass-max-terminal-size=: a parked window of 500×200 cells, the default bound, holds about 50 MB.

* Performance

The owner sends, for each viewer, the ranges it has not seen, read from the buffer when sent: a slow viewer costs bounded memory, and changes made meanwhile coalesce. Sending yields to the command loop every 4 ms. Between two Emacs processes on one host, a 100 MB buffer opens in 0.7 s, 100 000 small appends and a 50 MB/s stream arrive exactly with 20–30 ms of median latency, and terminals rewritten 60 times a second cost about 1 ms a tick; across SSH from a Mac to a Windows host on the local network, the same, the stream included. See [[file:doc/benchmarks.org][the benchmarks]], measured with =make bench=.
