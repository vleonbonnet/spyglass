#+TITLE: spyglass
#+OPTIONS: toc:nil

Spyglass mirrors live buffers from one Emacs into another, on the same host or across SSH. An owner shares buffers; a viewer opens read-only mirrors of them that follow every change, with faces, display properties, overlays and the owner's cursor, and sends the keys typed in them back. Shells, comint buffers and terminals (Eat, Ghostel, vterm) mirror as well as ordinary buffers, including terminals that write without modification hooks; a broken connection comes back on its own and mirrors resume where they were.

It is a library: it knows nothing of what the buffers hold. A session manager such as drover uses it to show, on one machine, agent sessions living in another machine's Emacs.

* Requirements

- Emacs 30.1 or later, for its built-in JSON parser; tested on 31.1 on macOS and on Windows (MSYS2 UCRT64). No other package.
- For another host: an SSH client whose =-W= forwards standard input and output to a port (OpenSSH, including Windows's OpenSSH server), and a shell there knowing =cat=.
- Optionally Eat, Ghostel or vterm on the owner: their adapters load with them.

* Installation

#+begin_src emacs-lisp
  (use-package spyglass
    :ensure (:host github :repo "vleonbonnet/spyglass"))
#+end_src

* Quick start

** On the owner

#+begin_src emacs-lisp
  (spyglass-server-start)                     ; 127.0.0.1, random port and token
  (spyglass-share (get-buffer "*shell*"))
#+end_src

The server listens on 127.0.0.1 only and writes its port and a random token to =spyglass-registration-file= (=~/.emacs.d/spyglass/server.json=), readable by you alone. Interactively, =M-x spyglass-share-current-buffer= starts the server and shares the current buffer.

** On the viewer

#+begin_src emacs-lisp
  (setq conn (spyglass-connect (spyglass-ssh-transport "otherhost") :name "otherhost"))
  (spyglass-connection-shares conn)             ; announced by the owner
  (pop-to-buffer (spyglass-open conn "*shell*"))
#+end_src

=spyglass-ssh-transport= reads the remote registration file with =ssh HOST cat FILE= (=spyglass-remote-registration-file=), then runs =ssh -W 127.0.0.1:PORT HOST= for the stream; =spyglass-ssh-program= names the SSH client. Interactively: =M-x spyglass-connect-host=, then =M-x spyglass-open-share=.

** In a mirror

Printing characters, =RET=, =TAB=, =DEL=, the arrows and =ESC= go to the owner; =C-c C-c=, =C-c C-d=, =C-c C-z= and =C-c C-j= send control characters, =C-c C-q= the next key, =C-c C-s= a string; =C-c C-f= toggles following the owner's cursor; =C-c C-k= closes the mirror. The header line tells where the mirror comes from and whether it is live, reconnecting or closed.

* API

Nothing below prompts; every function returns at once, and what happens on the network is reported through callbacks and hooks, never signaled into timers or process filters.

** Sharing

- =(spyglass-share &optional BUFFER &key ID READ-ONLY INPUT CAPTURE)= :: Share BUFFER (default: current) under ID (default: its name) and return the share. READ-ONLY refuses input; INPUT is a function applying viewers' input instead of the default; CAPTURE is =auto=, =shadow= or =direct= (see [[file:doc/design.org][the design notes]]). Sharing again updates the options given. Mirrors are never shared.
- =(spyglass-unshare BUFFER-OR-SHARE)= :: Stop sharing; viewers' mirrors close with the reason "unshared". Killing a shared buffer does the same ("killed").
- =(spyglass-shares)=, =(spyglass-share-of BUFFER)=, =(spyglass-share-viewers SHARE)=, =(spyglass-share-stats SHARE)= :: Shares, a buffer's share, its subscriptions, its counters and samples (main-thread ticks, latencies, bytes).
- =(spyglass-notify &optional BUFFER BEG END PROPS-ONLY)= :: Tell spyglass that BUFFER changed between BEG and END without modification hooks. Code writing with =inhibit-modification-hooks= bound should call it, as the Eat and Ghostel adapters do; without it changes are still found, by comparing the whole buffer at most every ten times the cost of a comparison.
- =spyglass-input-function= (buffer-local) :: How viewers' input applies in this buffer: a function of (KIND VALUE), KIND =string= with text or =key= with a key such as ="RET"=. Adapters set it; =spyglass-default-input= types into comint buffers, sends to processes as a terminal would, or inserts at point.
- =spyglass-submit-function= (buffer-local) :: The command RET runs in a comint buffer, =comint-send-input= by default; a front end such as agent-shell sets =agent-shell-submit= here.
- =spyglass-point-function= (buffer-local) :: The position viewers follow, point by default; terminal adapters give the terminal's cursor.
- =spyglass-share-functions=, =spyglass-share-state-functions= :: Hooks run on each new share, and on a share's events (=subscribed=, =unsubscribed=, =unshared=).

** Connecting

- =(spyglass-server-start &key PORT FILE)=, =(spyglass-server-stop)=, =(spyglass-server)= :: The listener on 127.0.0.1, its registration file, the running server.
- =(spyglass-connect TRANSPORT &key NAME CALLBACK PLIST)= :: Connect through TRANSPORT and return the connection, which connects again whenever its stream breaks, until =spyglass-disconnect=. CALLBACK gets =(CONNECTION EVENT DATA)= for =state=, =error= and =shares=.
- Transports: =(spyglass-ssh-transport HOST &key PROGRAM FILE ARGS)=, =(spyglass-file-transport &optional FILE)= for this host, =(spyglass-tcp-transport HOST PORT TOKEN)=. A transport is any function called with a continuation DONE, which it calls with a process streaming to the peer's server and the token, or with nil and a message; drover can supply its own.
- =(spyglass-disconnect CONNECTION)=, =(spyglass-connections)=, =(spyglass-connection-state CONNECTION)= (=connecting=, =open=, =reconnecting=, =closed=), =(spyglass-connection-shares CONNECTION)=, =(spyglass-list-shares CONNECTION CALLBACK)=, =(spyglass-connection-label CONNECTION)=.
- =spyglass-connection-state-functions=, =spyglass-shares-changed-functions=, =spyglass-error-functions= :: Hooks on every connection's state, a peer's shares, and errors.
- =spyglass-connection-attach-functions=, =spyglass-connection-detach-functions= :: Hooks run with a connection as each stream's handshake succeeds, and with (CONNECTION FINAL) as a stream ends, FINAL non-nil when the connection will not come back.
- =(spyglass-connection-set-heartbeat CONNECTION INTERVAL TIMEOUT)= :: Heartbeats of one connection: every INTERVAL seconds of silence, the peer dropped after TIMEOUT, instead of =spyglass-heartbeat-interval= and =spyglass-heartbeat-timeout=.

** Channels

Applications built on spyglass talk over its connections through channels: named streams of messages, each message a JSON object.

- =(spyglass-register-channel NAME HANDLER &key REQUEST ATTACH DETACH)= :: HANDLER gets =(CONNECTION MESSAGE)= for each message; REQUEST =(CONNECTION MESSAGE REPLY)= for each request, and calls REPLY once, now or later, with an answer or with nil and an error; ATTACH and DETACH hear the connection's streams open and end, as the hooks above.  =(spyglass-unregister-channel NAME)=.
- =(spyglass-channel-send CONNECTION NAME MESSAGE)= :: MESSAGE is a plist as =json-serialize= takes it (objects as plists, arrays as vectors, =:false=, nil as null); text JSON cannot carry, raw bytes or surrogates, is replaced by U+FFFD.  It arrives as =json-parse-string= returns it, never given to =read=.  Messages go in order while the stream lives; those queued when it breaks are dropped.
- =(spyglass-channel-request CONNECTION NAME MESSAGE CALLBACK &optional TIMEOUT)= :: CALLBACK gets =(REPLY ERROR)= once: the answer, or a message when the peer refused, no channel answers there, the time ran out (=spyglass-channel-request-timeout=) or the stream ended first.
- Large messages :: Past =spyglass-channel-chunk-size= (256 KB) a message goes in chunks, at most =spyglass-channel-window= (1 MB) of them unacknowledged, sent from timers in ticks of =spyglass-channel-tick-budget=; none may exceed =spyglass-channel-max-size= (32 MB), on either end.  =(spyglass-channel-stats CONNECTION)= counts messages, bytes and chunks.

** Mirrors

- =(spyglass-open CONNECTION SHARE-ID &key BUFFER-NAME CALLBACK)= :: Open a mirror and return its buffer, which fills asynchronously. CALLBACK gets =(MIRROR EVENT DATA)= for =state= and =error=.
- =(spyglass-close MIRROR-OR-BUFFER)= :: Stop updating; the buffer stays. Killing a mirror closes it.
- =(spyglass-mirror-state BUFFER)= (=opening=, =live=, =reconnecting=, =closed=), =(spyglass-mirror-closed-reason BUFFER)=, =(spyglass-mirror-connection BUFFER)=, =(spyglass-mirror-share-id BUFFER)=, =(spyglass-mirror-owner-point BUFFER)=, =(spyglass-mirror-stats BUFFER)=, =(spyglass-mirrors &optional CONNECTION)=.
- =(spyglass-mirror-send-string STRING &optional BUFFER)=, =(spyglass-mirror-send-key KEY &optional BUFFER)= :: Send input to the owner. The owner's refusals come back through the mirror's callback and =spyglass-error-functions=.
- =spyglass-mirror-state-functions= :: Hook run with (BUFFER STATE).
- =spyglass-mirror-follow=, =spyglass-mirror-show-cursor= :: Follow and show the owner's cursor.

* Terminals

Eat and Ghostel write their buffers with modification hooks inhibited; their adapters, loaded with them, tell spyglass the range written after each redraw, give the terminal's cursor and type through the terminal's own key handling. vterm's module writes with hooks; its adapter types through vterm's key translation. Ghostel renders only buffers shown in a window: a hidden Ghostel terminal on the owner does not change, nor do its mirrors. A terminal mirror is text and faces: the viewer's window size does not resize the owner's terminal.

* Security

The server binds 127.0.0.1 only; other hosts reach it through SSH. Clients must present the 256-bit token of the registration file, compared in constant time. Frames are limited to 64 KB before authentication and 64 MB after. Nothing received is ever read or evaluated: headers are JSON, Lisp values in them are decoded as data, and the viewer reduces every face, display specification and string to forms redisplay shows without evaluating anything (no images, no =:eval=, no =when=, no function as a height). Input from a viewer reaches only the share's input function, and a share made =:read-only= refuses it.

* Performance

The owner sends, for each viewer, the ranges it has not seen, read from the buffer when sent: a slow viewer costs bounded memory, and changes made meanwhile coalesce. Sending yields to the command loop every 4 ms. Between two Emacs processes on one host, a 100 MB buffer opens in 0.7 s, 100 000 small appends and a 50 MB/s stream arrive exactly with 20–30 ms of median latency, and terminals rewritten 60 times a second cost about 1 ms a tick; across SSH from a Mac to a Windows host on the local network, the same, the stream included. See [[file:doc/benchmarks.org][the benchmarks]], measured with =make bench=.
